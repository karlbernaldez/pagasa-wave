# WaveLab Overview

## Product Summary

Question: What is WaveLab?
Answer:
WaveLab is a web-based marine forecast operations platform used by forecasting teams to create, edit, review, revise, approve, and publish marine forecast products.

Question: What does WaveLab do?
Answer:
WaveLab helps operational forecasting teams manage the full lifecycle of forecast chart products.

Core capabilities include:
- creating forecast projects
- editing marine forecast charts
- adding map annotations and forecast markers
- managing project workflows
- submitting work for review
- comparing revisions between versions
- approving or rejecting forecast outputs
- publishing finalized forecast products
- tracking project activity and review history
- guiding users through documented workflows via the chatbot assistant

Question: Is WaveLab a wave simulation engine?
Answer:
No.
WaveLab is not the numerical forecasting engine itself. It is the operational platform used to manage forecast product workflows and forecast chart authoring.

Question: Who uses WaveLab?
Answer:
WaveLab is designed for operational forecasting users such as Forecasters and Admin reviewers.

## Main Work Areas

## Project Library
Purpose:
The Project Library is where users create, search, organize, and manage forecast projects.

Users can:
- create projects
- search projects
- filter by workflow status
- sort projects
- open projects in Studio
- review project summaries

## Studio Workspace
Purpose:
Studio is the interactive map editing workspace.

Users can:
- add forecast markers
- draw annotations
- manage map layers
- edit marine forecast content
- save project changes
- prepare submissions for review

Studio becomes read-only when workflow rules lock editing.

## Review Workspace
Purpose:
The review workspace allows Admin users to inspect submitted forecast products.

Admins can:
- review submitted projects
- compare revisions
- add review comments
- request revisions
- approve projects
- reject projects
- publish approved products

## Notifications
Purpose:
Notifications inform users about project workflow activity.

Examples:
- project submitted
- revision requested
- project approved
- project rejected
- project published

## User Roles

### Forecaster
Responsibilities:
- create draft projects
- add forecast annotations
- submit projects for review
- revise projects when requested

### Admin
Responsibilities:
- review submitted projects
- compare revisions
- request changes
- approve projects
- publish final outputs

## Workflow Summary
Typical project lifecycle:
Draft → Submitted → Under Review → Revision Requested → Approved → Published

Alternative states:
- Rejected
- Archived
