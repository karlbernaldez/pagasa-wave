# Forecast Terminology

This document defines the canonical user-facing and architecture vocabulary for WaveLab forecast preparation, review, approval, publication, and future RBAC/navigation work.

## Core Domain Vocabulary

### Forecast

Definition:

The overall WaveLab operational and business domain for preparing, reviewing, approving, publishing, and archiving marine forecast products.

Usage rule:

Use `Forecast` as a domain or feature-area term, not as the name of a persistence entity.

Examples:

- Forecasts
- Forecast workflow
- Forecast permissions
- Forecast operations

### Forecast Package

Definition:

The user-facing workflow aggregate representing one complete forecast production set for a forecast date or cycle. A Forecast Package contains the required Forecast Charts and carries the package-level workflow state.

Current WaveLab package contents include:

- Wave Analysis
- 24-hour Wave Forecast
- 36-hour Wave Forecast
- 48-hour Wave Forecast

Typical package lifecycle:

Draft -> Submitted -> Under Review -> Revision Requested or Rejected -> Approved -> Published -> Archived

Usage rule:

Submission, review, approval, publication, and archival should be described primarily in terms of the Forecast Package when those actions apply to the complete operational set.

### Forecast Chart

Definition:

One operational chart or forecast product contained within a Forecast Package.

Examples:

- Wave Analysis
- 24-hour Wave Forecast
- 36-hour Wave Forecast
- 48-hour Wave Forecast

Implementation mapping:

During the current migration period, an individual Forecast Chart is backed internally by the existing `Project` persistence model and may still be addressed internally by a `projectId`.

Usage rule:

Use `Forecast Chart` in new user-facing workflow, navigation, documentation, and RBAC terminology. Do not expose `Project` as a new user-facing concept when `Forecast Chart` is the intended business meaning.

### Studio

Definition:

The interactive map workspace used to inspect or edit a Forecast Chart, including forecast layers, annotations, drawing tools, labels, and related chart-editing controls.

Usage rule:

Studio is a tool/workspace, not a forecast workflow entity. A user opens a Forecast Chart in Studio.

### Project

Definition:

An existing internal persistence and implementation concept used to store an individual Forecast Chart.

Usage rule:

`Project` may remain in database models, route parameters, controllers, tests, and internal code while the system migrates. It should not be introduced into new user-facing terminology, navigation labels, or normal forecast RBAC permission names.

### Charts

Definition:

A presentation-oriented label that may be used on the public-facing site for published forecast products.

Usage rule:

Internal operational workflow terminology should prefer `Forecast Chart`. Public navigation may continue to use `Charts` where that label is clearer for public viewers.

## Workflow Vocabulary

### Draft

Definition:

A Forecast Package that is still being prepared and may be edited by users with the required forecast and Studio permissions.

### Submitted

Definition:

A Forecast Package that has been submitted for review and is no longer in ordinary editing state until the workflow permits revision.

### Under Review

Definition:

A Forecast Package currently being evaluated by a user with review permission.

### Revision Requested

Definition:

A Forecast Package returned for required changes before it can proceed through review again.

### Approved

Definition:

A Forecast Package that has passed the approval step and is eligible for publication subject to publication permission and workflow rules.

### Rejected

Definition:

A Forecast Package that did not pass review and is not eligible to proceed to approval or publication in its current workflow instance.

### Published

Definition:

A finalized Forecast Package released through the approved publication workflow. Published forecast content is not ordinarily editable.

### Archived

Definition:

A Forecast Package retained for historical or records purposes and no longer active in the normal forecast-production workflow.

### Review Comment

Definition:

A reviewer remark attached to a Forecast Package or Forecast Chart to document observations, decisions, or requested changes.

### Approval

Definition:

A workflow decision indicating that the Forecast Package has satisfied the approval step.

### Publication

Definition:

The controlled release of an approved Forecast Package or its resulting forecast products to the intended audience.

## Marine Forecast Vocabulary

### Significant Wave Height

Definition:

A standard marine wave metric often abbreviated as SWH.

### Swell Period

Definition:

The characteristic timing associated with swell wave energy.

### Peak Period

Definition:

The dominant energy wave period.

### Wind Sea

Definition:

Wave conditions generated by local wind forcing.

### Swell

Definition:

Wave energy propagated from distant generating systems.

### Forecast Cycle

Definition:

A scheduled forecast production interval.

### Forecast Update

Definition:

A refreshed forecast output.

### Forecast Valid Time

Definition:

The time period for which a forecast applies.

### Marine Hazard

Definition:

A marine condition requiring operational awareness.

## RBAC Naming Contract

Future permission-driven architecture should follow these naming boundaries:

- `forecast.*` controls normal forecast-domain workflow capabilities.
- `studio.*` controls access to and editing capabilities within Studio.
- User Types are permission bundles only and must not determine normal forecast workflow behavior by role name.
- Legacy `projects.*` permissions may remain temporarily for compatibility during migration but should not be the target naming for normal forecast workflow authorization.

## Architecture Summary

```text
Forecasts (domain)
└── Forecast Package (workflow aggregate)
    ├── Wave Analysis (Forecast Chart -> internal Project)
    ├── 24h Wave Forecast (Forecast Chart -> internal Project)
    ├── 36h Wave Forecast (Forecast Chart -> internal Project)
    └── 48h Wave Forecast (Forecast Chart -> internal Project)

Forecast Chart
└── opened and inspected/edited in Studio
```

This terminology contract is intentionally non-destructive. It does not require immediate renaming of the existing Mongo `Project` model, API route parameters, or persisted identifiers.
